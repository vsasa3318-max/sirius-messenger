# SIRIUS — мессенджер

Адаптивный тёмный веб-мессенджер с настоящим сервером: регистрация и вход, уникальные `@username`, профили со статусом, поиск пользователей, личные и групповые чаты, сообщения в реальном времени через Socket.IO, отправка изображений и документов.

## Возможности

- Регистрация по email и паролю; пароли хешируются bcrypt.
- Вход и сессии на JWT (7 дней).
- Уникальные имена пользователей `@username`.
- Профиль: статус и описание «О себе».
- Поиск пользователей по имени, включая запросы с `@`.
- Личные диалоги и группы до 50 участников.
- Сообщения в реальном времени; Socket.IO повторно синхронизирует комнаты чатов после подключения и создания новых диалогов.
- Фото и документы до 10 MiB; доступ к вложениям проверяется по членству в чате, ссылки на файлы подписаны и действуют 10 минут.
- SQLite и папка загрузок хранятся на постоянном диске Render.
- API автоматически выбирает тот же origin (`/api`). Для отдельного фронтенда можно задать `window.SIRIUS_API_BASE` или `<meta name="api-base" content="https://your-server.onrender.com/api">` до основного скрипта.

## Локальный запуск

Требуется Node.js 20+.

```bash
npm install
npm start
```

Открой http://localhost:3000. При локальном запуске секрет JWT имеет dev-значение; для production он обязателен и должен быть случайным.

Пример `.env`:

```env
PORT=3000
JWT_SECRET=замени-на-длинный-случайный-секрет-не-короче-24-символов
DATA_DIR=./data
UPLOAD_DIR=./uploads
# Только если фронтенд размещён на другом домене:
ALLOWED_ORIGINS=https://your-frontend.example
```

## Размещение на Render

1. Создай GitHub-репозиторий и загрузи в него **всё содержимое папки** `sirius-messenger`.
2. В Render выбери **New → Blueprint**, подключи репозиторий и подтверди создание сервиса по `render.yaml`.
3. Дождись сборки и статуса **Live**.
4. Открой выданный Render URL. Фронтенд и API работают с одного домена, отдельная настройка адреса API не нужна.

`render.yaml` создаёт `JWT_SECRET` автоматически и подключает persistent disk в `/var/data`. База SQLite и загруженные файлы сохраняются при перезапуске сервиса.

### Если фронтенд остаётся в OrangesCloud

Этот проект уже разрешает запросы с `https://orangescloud.pages.dev` через `ALLOWED_ORIGINS`. После создания сервиса Render скопируй его URL, например `https://sirius-messenger.onrender.com`, и в HTML сайта OrangesCloud добавь в секцию `<head>` строку (замени адрес на свой реальный URL):

```html
<meta name="api-base" content="https://sirius-messenger.onrender.com/api">
```

Фронтенд загружает Socket.IO с того же API-сервера автоматически, поэтому отдельно менять адрес скрипта Socket.IO не нужно. Не добавляй `/` после `api`. Если OrangesCloud не позволяет редактировать HTML, понадобится обновить загруженный файл сайта этой настройкой.

## Важные ограничения перед публичным запуском

Это готовая основа для небольшого проекта, но не промышленная платформа. Вложения ограничены 10 MiB и проверяются по MIME-типу, однако для открытой регистрации стоит добавить антивирусную проверку, подтверждение email, восстановление пароля, модерацию и резервное копирование. SQLite на одном persistent disk подходит для одного экземпляра сервиса; для масштабирования на несколько экземпляров используй PostgreSQL и объектное хранилище.

Не публикуй `.env` и не передавай никому `JWT_SECRET`.
